# Pasalo

[English](technical.md) · [Español](technical.es.md) · **Русский**

Pasalo передаёт файлы, папки и текст между вашими устройствами в одной сети или человеку из другой сети, который согласится подключиться к вам. Прерванная передача продолжается с того места, где остановилась.

Pasalo работает на **macOS, Windows, Linux и Android**. Ядро написано на Rust, приложение собрано на [Tauri 2](https://tauri.app).

## Возможности

- **Сама находит устройства в вашей сети.** Без аккаунтов и настройки. Работает без интернета.
- **Без интернета, пока вы сами не решите.** После запуска Pasalo общается только с локальной сетью и ничего не отправляет в интернет. Кнопка **Подключиться** показывает, кто ещё в сети, и позволяет попросить о подключении; если собеседник согласится, вы будете подключены только друг к другу через [iroh](https://iroh.computer), без проброса портов.
- **Вы решаете, что принимать.** Каждая передача файлов приходит как запрос, который можно принять или отклонить.
- **Тратит как можно меньше трафика.** Всё, что сжимается, сжимается (текстовый журнал на 9,9 МБ ушёл как 2,2 МБ); уже сжатые файлы (фото, видео, zip) идут как есть, без лишней траты батареи.
- **Продолжает прерванные передачи.** Если соединение оборвалось, приложение закрыли или отправитель перезапустился, следующая попытка продолжит с последнего полученного байта. Каждый файл проверяется по BLAKE3.
- **Справляется с большими файлами и папками.** Данные идут блоками по 256 КБ, поэтому размер файла не ограничен памятью. Тысячи мелких файлов передаются быстро.
- **Отправляет текст:** ссылки, пароли, заметки.
- **Говорит на вашем языке:** интерфейс на английском, испанском и русском. Язык берётся из системы, его можно сменить в приложении.

## Как пользоваться

### В одной сети

Откройте Pasalo на обоих устройствах. Через несколько секунд они появятся друг у друга в списке **Устройства**. Затем:

- перетащите файлы или папки на устройство (на компьютере) или
- нажмите **Файлы**, **Папка** или **Текст** у нужного устройства.

На другом устройстве в разделе **Активность** появится, кто хочет отправить что и какого размера, с кнопками **Принять** и **Отклонить**. Если никто не ответит за 2 минуты, отправка отменяется. Если принятая передача прервалась, при продолжении повторно не спрашивается.

Если устройство не появилось, введите его IP в поле **Добавить по IP**. Обычно так бывает в сетях, где заблокирован broadcast: гостевой Wi-Fi, некоторые корпоративные сети.

### Между разными сетями

1. Оба нажимают **Подключиться**. До этого Pasalo ничего не пытается делать за пределами локальной сети.
2. В разделе **Сейчас в сети** видны остальные подключённые. Один из вас нажимает **Подключить** рядом с другим.
3. Другой получает запрос и нажимает **Принять** (или **Отклонить**).
4. Вы подключены: оба уходите с сервера, больше никто вас не видит и не может с вами связаться, а друг у друга вы появляетесь в **Устройствах**, чтобы отправлять файлы, переписываться и звонить, как в локальной сети.
5. **Отключиться** завершает подключение с обеих сторон и возвращает режим только локальной сети. После закрытия приложения в следующий раз оно тоже запускается отключённым.

Сервер ([`server/`](../server/README.md), для Vercel с MongoDB) только знакомит вас: файлы, сообщения и звонки через него не идут. iroh соединяет устройства напрямую, когда это позволяют сети, а иначе через relay n0. Адрес сервера указывается в ⚙ Настройках.

### На Android

- На **Android 17 и новее** разрешите доступ к **локальной сети**, когда Pasalo попросит. Без него Android молча блокирует весь трафик с локальной сетью.
- **Не закрывайте Pasalo, пока идёт приём.** Android замораживает приложения в фоне, и передача останавливается. Она продолжится, когда вы вернётесь в приложение.
- Полученные файлы сохраняются в `Download/Pasalo`.
- Нужен Android 8.0 или новее.
- Отправлять можно файлы, но не целые папки. Выбранные файлы перед отправкой копируются в кэш приложения, поэтому для отправки файла на 10 ГБ нужно ещё 10 ГБ свободного места.

## Чат и звонки

Кнопка **Чат** есть у устройств вашей сети с Pasalo и у собеседника, с которым вы подключились:

- **Сообщения и изображения** идут напрямую между двумя устройствами через iroh. Перед отправкой изображения уменьшаются до 1600 px. Недоставленные сообщения ждут и уходят, как только устройство станет доступно. Неиспользуемое соединение закрывается через 90 с, чтобы не тратить трафик на его поддержание.
- **Голосовые сообщения** (AAC или Opus, до 5 мин), **фото на один просмотр** (удаляются у обоих после просмотра; скриншоты блокируются на Android, macOS и Windows) и **приватные чаты** (замок рядом с кнопками звонка: история удаляется на обоих устройствах при отключении). Каждый звонок остаётся в чате с длительностью и расходом трафика.
- **Голосовые звонки**, сделанные на Rust, без WebRTC и серверов: Opus или Codec2 поверх ненадёжных датаграмм QUIC. Качество можно менять во время звонка, и собеседник переключается тоже. Замеры всего трафика, когда обе стороны говорят одновременно (худший случай):

  | Качество | Трафик | Раньше | Доп. задержка |
  |---|---|---|---|
  | Высокое (Opus 24 кбит/с, пакеты по 40 мс) | ~42 кбит/с | ~57 | ~80 мс |
  | Обычное (Opus 12 кбит/с, 60 мс) | ~26 кбит/с | ~35 | ~110 мс |
  | Низкое (Opus 6 кбит/с, 120 мс) | ~19 кбит/с | ~19 | ~360 мс |
  | Минимальное (Codec2 1300 бит/с, 160 мс) | ~9 кбит/с | ~9 | ~440 мс |

  Во время тишины ничего не отправляется, поэтому тот, кто только слушает, тратит гораздо меньше (около 6–7 кбит/с в режиме «Обычное», почти всё — подтверждения QUIC). В режимах «Низкое» и «Минимальное» каждый пакет несёт и предыдущий, поэтому одиночные потери восстанавливаются. Подтверждения объединяются в пределах одного RTT: в мобильной сети, где задержка больше, чем в домашнем Wi-Fi, трафик немного ниже, чем в таблице.
- **Видеозвонки** идут через то же соединение iroh, что и голос, без WebRTC, STUN и TURN: камера сжимается в приложении через WebCodecs (VP9, H.264 или VP8), каждый кадр идёт в своём потоке QUIC. Качество — примерно от 40 до 300 кбит/с (160–480 px, 6–20 кадр/с); если сеть теряет кадры, качество само снижается на обеих сторонах. Размытие фона (по желанию) отправляет на 30 % меньше видео.

На Android разрешите доступ к микрофону (и к камере для видео). На компьютере у звонков только простое подавление эха: используйте наушники. 

## Командная строка

CLI `pasalo` использует тот же протокол, что и приложение, поэтому они понимают друг друга.

```sh
pasalo listen                          # принимать в Загрузки/Pasalo; спрашивает перед приёмом (s/n)
pasalo listen --yes --dir ~/Inbox      # принимать всё, в другую папку
pasalo listen --offline                # только локальная сеть, без интернета
pasalo listen --server https://….vercel.app --connect "Pixel"   # зайти на сервер и попросить подключения
pasalo peers                           # список устройств в сети
pasalo send 192.168.1.20 photo.jpg     # отправить на IP (или IP:порт)
pasalo send "Office PC" Photos/        # отправить устройству по имени
pasalo send <код> big.iso              # отправить удалённому устройству по коду
pasalo text <получатель> "привет"      # отправить текст
pasalo chat <получатель> "привет" --image a.jpg  # сообщение в чат (код или имя в сети)
pasalo call <получатель> --mode minimum --voice-in voice.raw   # тестовый звонок с аудиофайлом
```

`--name` меняет имя, под которым вас видят другие. `PASALO_CONFIG_DIR` позволяет запустить несколько экземпляров на одной машине для тестов. Сообщения самого CLI пока на испанском.

## Как это работает

| | |
|---|---|
| Обнаружение | UDP broadcast на порт **4645**: на `255.255.255.255` и на broadcast-адрес каждого интерфейса. |
| Передача в сети | TCP на порт **4646**. |
| Удалённая передача | QUIC поверх [iroh](https://iroh.computer) (ALPN `pasalo/1`) с обходом NAT; публичные relay-серверы n0 служат запасным путём. |
| Протокол | Управляющие сообщения в JSON с префиксом длины; содержимое файлов идёт между ними: блоками со сжатием zstd, если оба устройства его понимают (уровень 1 в локальной сети, 3 между сетями), как есть со старыми версиями. |
| Запросы | Получатель не отвечает на предложение, пока пользователь не примет или не отклонит его (`Reject { reason: "declined" }`). |
| Подключение | iroh запускается без relay и DNS. **Подключиться** на ходу добавляет relay и DNS n0, сохраняя тот же код и порт; после подключения к собеседнику принимаются только его соединения. |
| Целостность | Хеш BLAKE3 каждого файла целиком проверяется, прежде чем файл занимает своё место. |
| Продолжение | Получатель хранит файлы `.pasalo-part` и небольшой журнал в `<папка>/.pasalo/`. Когда отправитель снова предлагает те же файлы, получатель отвечает, с какого байта продолжить. |

### Безопасность и приватность

- Pasalo не добавляет собственного шифрования. **Файлы, отправленные по локальной сети, не шифруются**: любой в той же сети может увидеть, что вы отправляете. То, что идёт через iroh (чат, звонки и всё с собеседником), зашифровано, потому что QUIC делает это всегда.
- **Ничего не приходит без вашего согласия.** Любой в вашей сети может попросить отправить вам файлы, но они придут, только если вы примете. Отдельные тексты приходят без вопроса.
- **Сервер видит ваше имя и тип устройства**, пока вы подключены, а ваш код iroh получает только тот, кого вы приняли. Аккаунтов нет: каждая сессия опознаётся случайным токеном.
- Ваш код хранится в файле `remote_key` в папке настроек приложения. Тот, у кого есть этот файл, может выдать себя за ваше устройство.

## Сборка из исходников

Нужны [Rust](https://rustup.rs) (stable) и [зависимости Tauri](https://tauri.app/start/prerequisites/) для вашей системы.

```sh
cargo test -p pasalo-core              # тесты (добавьте -- --ignored для теста через интернет)
cargo run -p pasalo-cli -- listen      # CLI
cd server && npm install && npm test  # тесты сервера (Node 20+)
cargo install tauri-cli --version "^2" --locked
cd app/src-tauri && cargo tauri dev    # приложение для компьютера
cargo tauri build                      # установщик для текущей системы
```

Для Android также нужны Android SDK и NDK, Java 17 и цели Rust:

```sh
rustup target add aarch64-linux-android armv7-linux-androideabi x86_64-linux-android
cd app/src-tauri && cargo tauri android build --apk
```

### Релизы

[`.github/workflows/release.yml`](../.github/workflows/release.yml) собирает все платформы и публикует pre-release на GitHub, когда вы отправляете тег вида `v0.1.0-rc1`:

```sh
git tag v0.1.0-rc1 && git push origin v0.1.0-rc1
```

Чтобы подписать APK для Android, добавьте в репозиторий эти секреты. Без них workflow опубликует неподписанный APK.

| Секрет | Значение |
|---|---|
| `ANDROID_KEYSTORE_BASE64` | `base64 -i pasalo-release.jks` |
| `ANDROID_KEYSTORE_PASSWORD` | Пароль хранилища ключей (псевдоним ключа `pasalo`) |

## Структура проекта

```
crates/pasalo-core   обнаружение, протокол, отправка, приём, сжатие, iroh, клиент сервера
crates/pasalo-cli    команда pasalo
crates/pasalo-call   голосовые звонки (кодеки и пакеты)
server               сервер подключения для Vercel с MongoDB (см. server/README.md)
app/src-tauri        приложение Tauri (Rust) и проект Android в gen/android
app/ui               интерфейс (HTML, CSS и JS без сборки), переводы в i18n.js
web                  Pasalo web (iroh и голос в WASM, для iPhone); публикуется в server/public/app
```
